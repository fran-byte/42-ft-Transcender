## Development Commands

All development is Docker-based. There are no local build steps outside containers.

```bash
make            # Full setup (certs, .env, nginx check) + start all services
make up         # Start containers (assumes setup already done)
make logs       # Stream all container logs
make stop       # Pause containers (preserves state)
make down       # Stop & remove containers (DB volume persists)
make re         # Full reset: fclean + up
make fclean     # Nuclear: removes containers, images, volumes, and ./data/postgres
make ps         # Container status
make prune      # Reclaim Docker disk space
```

**Dev mode** (no Nginx or monitoring — backend at `:3000`, frontend at `:5173`):
```bash
make dev        # Setup + start dev stack
make dev-logs   # Stream dev logs
make dev-down   # Stop dev stack
make dev-re     # Rebuild dev stack
```

**Setup utilities:**
```bash
make setup           # Run only the config phase (certs, .env, nginx check) without starting containers
sudo make hosts      # Add blackjack.local to /etc/hosts (run once)
make clean-config    # Remove generated certs and .env
make distclean       # fclean + clean-config (absolute zero)
```

Access: `https://blackjack.local` (after `sudo make hosts`) or `https://localhost`

**Frontend linting (inside container or with local Node):**
```bash
cd frontend && npm run lint
```

No test suite exists — `npm test` in backend exits with error by design.

## Environment Setup

`make` / `make setup` auto-generates `.env` with random credentials (interactive for Grafana). To create manually:
```
POSTGRES_USER=blackjack_user
POSTGRES_PASSWORD=<password>
POSTGRES_DB=blackjack_db
DB_HOST=db
JWT_SECRET=<openssl rand -hex 32>
DATA_PATH=./data
NODE_ENV=development
REACT_APP_API_URL=https://blackjack.local/api
GRAFANA_USER=admin
GRAFANA_PASSWORD=<password>
ALLOWED_ORIGIN=https://blackjack.local   # comma-separated for multiple origins
```

SSL certs are auto-generated by `make ensure-certs` at `secrets/certs/blackjack.local.crt` and `secrets/certs/blackjack.local.key`.

## Architecture

Seven Docker services (production compose):

```
Nginx (:80/:443) → Frontend (:5173) → Backend (:3000) → PostgreSQL (:5432)
                                        ↘ ML Service (:5000)
Prometheus (:9090) ← Backend /metrics
Grafana (:3001) ← Prometheus
cAdvisor (:8080)
```

- **Nginx** (`backend/nginx/conf.d/blackjack.conf`) — reverse proxy routing `/api` and `/socket.io` to backend, `/` to frontend. Note: `/ml` route is not wired in the current nginx config.
- **Backend** (`backend/`) — Express 5 + Socket.io. Hot reload via nodemon (volume-mounted source).
- **Frontend** (`frontend/`) — React 19 + Vite 7. Socket URL hardcoded to `""` (same origin via Nginx proxy) in `src/socket.js`.
- **ML Service** (`ml_service/app.py`) — Flask + Gunicorn serving a NumPy DQN model at `/predict`.
- **PostgreSQL** — Schema from `database/init.sql`. Data persisted at `./data/postgres`.
- **Prometheus/Grafana/cAdvisor** — Backend exposes `/metrics` (prom-client). Grafana at `localhost:3001`, Prometheus at `localhost:9090`, cAdvisor at `localhost:8080`.

## Backend Structure

The backend follows a layered architecture — entry point → Express app → routes → controllers → services → DB.

```
backend/
├── server.js                      # Entry: creates HTTP server, calls initSocket
├── app.js                         # Express setup: CORS, middleware, /api routes, /metrics
├── config/env.js                  # Centralized config (reads process.env, sets defaults)
├── db/pool.js                     # Single canonical pg Pool instance
├── routes/
│   ├── index.js                   # Mounts: /auth, /users, /leaderboard
│   ├── auth.js                    # POST register/login/logout, GET verify
│   ├── users.js                   # GET/POST balance, stats, history (all protected)
│   └── leaderboard.js             # GET / (protected)
├── controllers/authController.js  # Thin handlers: parse req → call service → send res
├── services/
│   ├── authService.js             # register/login: hashing, JWT, DB insert
│   ├── userService.js             # balance, stats, history, leaderboard DB operations
│   ├── gameService.js             # persistFinishedGame: writes game_history + updates balance
│   └── mlService.js               # callMLServiceEnhanced (HTTP to ml-service) + basicStrategyFallback
├── middleware/
│   ├── authMiddleware.js          # JWT cookie verification → sets req.user
│   └── errorMiddleware.js         # Central error handler
├── socket/
│   ├── index.js                   # initSocket: creates shared `games` map, wires handlers
│   ├── gameHandlers.js            # All socket events: join_game, place_bet, action_*, add_ai_player, disconnect, …
│   └── lobbyHandlers.js           # emitLobbyState (broadcast room list), get_lobby_state handler
└── game/
    ├── BlackjackGame.js           # All game logic: players, deck, rounds, AI bets, turn timers
    ├── Deck.js                    # 6-deck shoe (312 cards) with Fisher-Yates shuffle
    └── roomConfigs.js             # ROOM_CONFIGS map (source of truth for room metadata)
```

### REST API Routes

All routes are under `/api`:

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| POST | `/auth/register` | No | Create account, returns JWT cookie |
| POST | `/auth/login` | No | Login, returns JWT cookie |
| POST | `/auth/logout` | No | Clears JWT cookie |
| GET | `/auth/verify` | Yes | Validate cookie, return user |
| GET | `/users/balance` | Yes | Get balance |
| POST | `/users/balance` | Yes | Deposit/withdraw (`{ amount, type: "deposit"\|"withdraw" }`) |
| GET | `/users/stats` | Yes | Get game stats |
| POST | `/users/stats` | Yes | Update game stats |
| GET | `/users/history` | Yes | Last 5 game history entries |
| GET | `/leaderboard` | Yes | Top 3 users by balance |
| GET | `/metrics` | No | Prometheus metrics (prom-client) |

### Socket Events

Client→Server: `join_game`, `leave_room`, `get_lobby_state`, `place_bet`, `clear_bet`, `start_round`, `reset_round`, `action_hit`, `action_stand`, `action_double`, `add_ai_player`, `remove_ai_player`, `sync_wallet_balance`

Server→Client: `game_update`, `lobby_state`, `join_result`, `add_ai_result`, `remove_ai_result`, `bet_error`

### Game State Flow

1. Player joins → `player.chips` loaded from DB balance
2. Bets placed → in-memory only (no DB writes per bet)
3. Round finishes → `persistFinishedGame()` writes `game_history` + updates `users.balance` **before** broadcasting `game_update`
4. Frontend reads `myPlayer.chips` from `game_update` socket event — no separate balance API call needed
5. Wallet deposit/withdraw → REST `POST /api/users/balance` → client emits `sync_wallet_balance` → server updates `player.chips` in-memory

### AI Players

AI players use the DQN model via `mlService.callMLServiceEnhanced`. On failure, `basicStrategyFallback` (hardcoded basic strategy) is used. Bets are sized with Kelly Criterion (`calculateKellyBet` in `BlackjackGame.js`). The `onAITurn(botId, botPlayer, dealerVisibleCard)` callback in `BlackjackGame.js` drives the ML request; `games` map is shared across all socket handlers via closure in `socket/index.js`.

## Frontend Structure

```
frontend/src/
├── App.jsx          # React Router: all routes defined here
├── socket.js        # Socket.io client singleton (URL = "" → same origin via Nginx)
├── pages/           # Home, Login, Register, Profile, Lobby, Game, Terms, Privacy
├── components/      # Navbar, Footer, Card (3D flip), ProtectedRoute
└── styles/          # Auth.css, Game.css, Index.css
```

Auth state: JWT in httpOnly cookie (server) + `username`/`email`/`isLoggedIn` in localStorage (client cache). `ProtectedRoute` only checks localStorage — server-side validation happens on actual API/socket calls.

`Game.jsx` is 1200+ lines and handles all in-game UI, socket event subscription, and local state.

## ML Service

Model: Dueling Double DQN with PER — 5 inputs (`player_score`, `dealer_visible`, `usable_ace`, `true_count`, `can_double`) → 3 outputs (Q-hit, Q-stand, Q-double). Network: 256/128 hidden units. Weights at `ml_service/train/blackjack_dqn.npz`. Retrain with `ml_service/train/train.py` (requires GPU; uses `env_cuda.py` for vectorized CUDA env):
```bash
docker run --rm --gpus all --device /dev/dxg -v /usr/lib/wsl:/usr/lib/wsl:ro \
  -e LD_LIBRARY_PATH=/usr/lib/wsl/lib \
  -v $(pwd)/ml_service/train:/work/train blackjack-train:cuda
```
